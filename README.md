# Полимерная лаборатория

Учебная симуляция на **Python + Pygame** для изучения инерции, перерегулирования,
П-, ПИД-регуляторов и интегрального насыщения. Интерфейс и комментарии на русском.

## Запуск

Требуется Python 3.10 или новее.

**Windows:** запустите `run.bat` двойным щелчком. Батник сам создаст `.venv`,
установит зависимости и запустит симуляцию через Python из этого окружения.
При следующих запусках окружение используется повторно. Для первой установки
зависимостей нужен интернет. Батник работает независимо от текущей папки;
при ошибке окно остаётся открытым, чтобы можно было прочитать сообщение.
Батник выбирает Python 3.10–3.13: сначала команду `python`, затем версии,
доступные через `py`. Это позволяет использовать готовый пакет Pygame для Windows.

Ручной запуск без батника:

```powershell
python -m pip install -r requirements.txt
python main.py
```

По умолчанию включено **реле**, ускорение **×16**, цель **100 °C**.
Окно можно менять в размере; интерфейс масштабируется целиком. Рекомендуемый
размер — от 1280 × 854. Все данные рассчитываются локально, без сети.

## Управление

| Действие | Клавиша / элемент |
|---|---|
| Ручная мощность | `1`, затем ползунок «Команда вручную»; `↑` / `↓` меняют команду на 1% |
| Релейный регулятор | `2`. По датчику включает нагрев при 90 °C и ниже, выключает при 110 °C и выше |
| П-регулятор | `3` |
| ПИД-регулятор | `4` |
| Код студента | `5` |
| Пауза / продолжить | `Пробел` или кнопка |

| Новая загрузка и сброс статистики | `R` применяет выбранную массу. Режим, мощность источника и коэффициенты сохраняются |
| Перечитать `controller.py` | `F5`; память регулятора очищается |
| Скорость ×1 / ×4 / ×16 / ×64 | `+` / `−` или кнопки |
| Обдув — тепловое возмущение | `C`; потери тепла бочки увеличиваются втрое |
| Сохранить весь опыт в CSV | `E`, каталог `exports/` рядом с программой |
| Длина видимого окна графиков | Кнопка «Окно графиков»: 2 / 5 / 10 / 20 минут |
| Увеличить график температуры бочки и датчика | `Z` или кнопка «Бочка крупно». Кривая нагревателя скрывается, ось подстраивается под бочку |
| Значения на графике | Навести мышь на уже записанный участок. На графике температуры видны также мощность и команда регулятора |
| Справка | `F1`; во время справки модель приостановлена |
| Выбор элемента с клавиатуры | `Tab` / `Shift+Tab` |
| Изменение выбранного ползунка | `←` / `→`; также работает колесо мыши над ним |
| Нажатие выбранной кнопки | `Enter` или `Пробел` |

Пауза останавливает модельное время, реакцию и регулятор. Изменённые настройки
начинают влиять после продолжения расчёта. Экспорт доступен и на паузе.

## Где писать регулятор

Измените функцию **`regulator` в `controller.py`**. Сохраните файл, нажмите
`F5`, затем `5`. Перезапуск приложения не нужен.

```python
def regulator(temperature: float, dt: float, target: float, state: dict) -> float:
    error = target - temperature
    return 0.05 * error
```

Аргументы:

- `temperature` — показание датчика в °C. Датчик запаздывает относительно
  содержимого; регулятор не получает температуру самого нагревателя.
- `dt` — **0.25 секунды модельного времени**, независимо от FPS и ускорения.
- `target` — уставка **100 °C**.
- `state` — словарь памяти: храните интеграл, прошлое показание, состояние реле.
  Он очищается при сбросе опыта, успешном F5 и смене режима.

Выход — доля мощности: `0` выключает источник, `0.5` даёт 50%, `1` даёт 100%.
Фактическая электрическая мощность: `u * supply_kw`. Результат ограничивается
диапазоном `[0, 1]`. Исключение, `None`, NaN или бесконечность отключают мощность;
сообщение появляется внизу. Тепловой расчёт продолжается. Исправьте функцию и
нажмите F5. При синтаксической ошибке загрузки сохраняется предыдущая функция.

Один вызов функции должен делать один короткий расчёт. Не нужны `while`,
`sleep()` и измерение реального времени. Код выполняется в процессе приложения:
бесконечный цикл в функции остановит интерфейс до завершения процесса.

Встроенные П и ПИД находятся в `Simulation.control()` в `simulation.py`.
В `controller.py` уже есть рабочий пример ПИД. В режиме «Студент» можно менять
`kp`, `ki` и `kd` прямо в функции. При мощности 18 кВт сравните `ki = 0.0001`
и `ki = 0.01`. После каждого изменения сохраните файл, нажмите F5 и начните
новый опыт с `R`. Для сравнения с реле выберите режим `2`.
Ползунки Kp/Ki/Kd управляют встроенными режимами П и ПИД; в режиме «Студент»
коэффициенты определяются вашим кодом.

## Математическая модель

Это **условная учебная модель по заданным правилам**, а не описание реального
химического процесса или инструкция по изготовлению полиэтилена. Давление,
катализатор, фазовые переходы, перемешивание, изменение теплоёмкости при реакции
и тепло реакции не моделируются. Параметры выбраны для наглядного изучения САУ.

Два тепловых узла: нагреватель с температурой `Th` и бочка с температурой `T`.
Нагреватель запасает энергию, поэтому `u = 0` не означает мгновенного остывания.

```text
P = u * Pmax
Q = k * (Th - T)
Ch * dTh/dt = P - Q - ah * (Th - Ta)
Cr * dT/dt  = Q - ar * (T - Ta)
dTs/dt     = (T - Ts) / tau_sensor
```

| Параметр | Начальное значение |
|---|---|
| Температура окружающей среды и начальная температура | 20 °C |
| Максимальная мощность источника `Pmax` | 18 кВт, регулируется от 4 до 500 кВт |
| Теплоёмкость нагревателя `Ch` | 9 кДж/°C, регулируется от 2 до 20 кДж/°C |
| Теплоёмкость содержимого и бочки `Cr` | 42 кДж/°C |
| Тепловая связь `k` | 180 Вт/°C |
| Потери нагревателя `ah` | 8 Вт/°C |
| Потери бочки `ar` | 32 Вт/°C, при обдуве 96 Вт/°C |
| Постоянная времени датчика `tau_sensor` | 2 с |
| Начальная масса этилена | 1000 кг, регулируется от 10 до 10 000 кг |
| Максимальный выход `vmax` | 0.08 кг/с = 4.8 кг/мин |

Параметры задаются в `Parameters` в `simulation.py`. Изменять теплоёмкость лучше
перед новым опытом (`R`), чтобы сравнивать одинаковые начальные условия.
Переключение режима посреди опыта сохраняет температуры, состав и историю.

Скорость синтеза зависит от **температуры бочки**, а не показания датчика:

```text
если 90 <= T <= 110: v(T) = vmax * exp(-0.5 * ((T - 100) / 5)^2)
иначе:               v(T) = 0
```

В 100 °C выход максимален; при отклонении в обе стороны уменьшается.
Например: 95/105 °C → около 61% максимума, 98/102 °C → около 92%.
В граничных точках 90 и 110 °C синтез ещё идёт (около 14% максимума),
за пределами диапазона скорость сразу равна нулю, согласно условию задачи.
Расход этилена равен массе полученного полиэтилена; после исчерпания загрузки
синтез прекращается, тепловая модель продолжает работать.
В этой модели масса загрузки определяет запас сырья. Теплоёмкость бочки
и максимальная скорость синтеза заданы отдельно.

ПИД использует производную по измерению:

```text
e = target - Ts
u = Kp * e + Ki * integral(e dt) - Kd * dTs/dt
```

Начальные коэффициенты: `Kp = 0.05`, `Ki = 0.0001`, `Kd = 1.2`.
Диапазоны в интерфейсе — `Kp` от 0 до 10 (для П и ПИД), `Ki` от 0 до 0.2,
`Kd` от 0 до 100. Шкалы этих ползунков и источника мощности нелинейные,
чтобы малые значения было проще выбирать мышью. Колесо и стрелки меняют
значения фиксированными шагами.
Защита интегратора: ошибка не накапливается при насыщении, если она усиливает его.
При смене режима память сбрасывается; переключение не обязано быть плавным.
Электрический источник реагирует сразу; тепловая инерция создаётся самим
нагревателем и бочкой. Дополнительная задержка датчика видна на графике.

Шаг тепловой модели — **0.05 с**, период регулятора — **0.25 с**, запись графиков
и CSV — **0.5 с**. Все три интервала отсчитываются в модельном времени.
Длительные задержки кадров ограничивают продвижение времени: приложение может
замедлиться, но численный шаг не увеличивается и устойчивость не меняется.
Температурный график показывает бочку, нагреватель, датчик, цель и зону синтеза.
Поле «Перерегулирование» — максимальное превышение 100 °C **за весь текущий опыт**.
Показатели текущие, даже если загрузка уже полностью превратилась в полимер.

CSV содержит весь опыт от нуля, независимо от видимого окна: время в секундах,
три температуры, скорость в кг/с, накопленную массу, команду, электрическую
мощность, цель, обдув и режим. Формат UTF-8 с BOM, разделитель `;`, десятичная
точка; названия столбцов содержат единицы измерения.

## Предлагаемые опыты

1. Реле, 18 кВт, 9 кДж/°C. При нагреве реле держит 100% мощности, пока датчик
   не покажет 110 °C. После отключения нагреватель продолжает отдавать тепло,
   поэтому бочка ещё нагревается. Когда датчик остынет до 90 °C, реле снова
   включит источник. Между порогами реле сохраняет предыдущее состояние.
2. Повторите с 20 кДж/°C, затем с 4 кДж/°C. Перед каждым опытом нажимайте R.
3. Для опыта с **П-регулятором** выберите режим `3`, мощность 80 кВт, теплоёмкость
   9 кДж/°C и выключите обдув. Сравните `Kp = 0.02` и `Kp = 10`. Начинайте
   каждый опыт с `R`. С малым `Kp` температура устанавливается около 98 °C.
   С большим `Kp` она регулярно колеблется около цели даже после прогрева.
4. Для опыта с **ПИД** выберите режим `4`, мощность 18 кВт, `Kp = 0.05`,
   `Kd = 1.2` и ту же теплоёмкость 9 кДж/°C. Сравните `Ki = 0.0001` и
   `Ki = 0.01`, каждый раз начиная с `R`. При большом `Ki` после прогрева
   колебания продолжаются примерно от 98 до 105 °C.
5. После стабилизации включите обдув. Посмотрите, как меняется команда и
   восстанавливается температура.
6. Реализуйте свой ПИД в `controller.py`: сравните обычное интегрирование с
   защитой от насыщения. Попробуйте выключать нагрев раньше по скорости роста T.

Для исходных настроек за 1200 с реле даёт пик около 116.7 °C, встроенный ПИД
выходит примерно на 99.94 °C без превышения 100 °C. Это результат этой модели,
а не обещание для иных параметров или физического оборудования.

В опытах 3 и 4 включите «Бочка крупно» (`Z`) и дождитесь 30 модельных минут
(около 28 секунд при ×64). Сравните последние 10 минут: одиночный пик при
разогреве показывает перерегулирование, а повторяющиеся пики после разогрева
показывают, что температура не сходится к равновесию. Мощность ограничена
диапазоном 0–100% от выбранного предела, поэтому потеря устойчивости в этих
опытах видна как ограниченные автоколебания.

## Проверка без окна

Дополнительные библиотеки для тестов не нужны.

```powershell
python -m unittest discover -s tests -v
python main.py --headless --seconds 1200 --mode relay --screenshot artifacts/relay.png
python main.py --headless --seconds 1200 --mode pid --screenshot artifacts/pid.png
```

`--headless` выполняет заданное число модельных секунд, рисует кадр и завершается.
В обычном запуске `--mode pid` позволяет сразу выбрать ПИД; длительность `--seconds`
используется только в режиме без окна.

Файлы: `main.py` — запуск, `app.py` — интерфейс, `simulation.py` — модель и
встроенные регуляторы, `controller.py` — место для студенческого кода.
